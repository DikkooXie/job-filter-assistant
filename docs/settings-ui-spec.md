# 设置页界面规格（v2）

设置页重构的唯一验收依据。原型效果图没有入库（本地文件，含个人材料），所以这里把颜色、尺寸、结构和每个页面的字段来源都写死。实现时量取数值以本文件为准。

不改变任何功能、存储字段或后台消息；只改布局、样式和必要的文案。

## 1. 颜色

只作用于设置页，不要改全局主题，避免影响浮窗和侧边栏（它们与设置页共用组件和样式表）。

```css
.settings-root{
  --s-page:#f1f2f0; --s-surface:#f1f2f0; --s-surface-2:#e9ecea; --s-inset:#e3e8e5; --s-field:#f6f7f5;
  --s-border:rgba(20,32,38,.10); --s-border-strong:rgba(20,32,38,.16);
  --s-ink-1:#16202a; --s-ink-2:#4b5865; --s-ink-3:#5e6b75;
  --s-accent:#1c6b5e; --s-accent-soft:rgba(28,107,94,.09); --s-accent-line:rgba(28,107,94,.28); --s-on-accent:#f7fbfa;
  --s-up:#1d7a4c; --s-down:#b23b48; --s-down-soft:rgba(178,59,72,.08); --s-warn:#94651a;
  --s-btn-bg:#18232c; --s-btn-ink:#f7fafa; --s-focus:rgba(28,107,94,.22);
  --s-switch-off:#c4cdd3;
  --s-shadow:0 1px 2px rgba(16,28,34,.05),0 8px 24px -16px rgba(16,28,34,.22);
}
@media (prefers-color-scheme: dark){
  .settings-root{
  --s-page:#161d22; --s-surface:#161d22; --s-surface-2:#1a2228; --s-inset:#1d262c; --s-field:#121a1f;
  --s-border:rgba(214,230,238,.10); --s-border-strong:rgba(214,230,238,.16);
  --s-ink-1:#e7edf0; --s-ink-2:#aebac3; --s-ink-3:#828f99;
  --s-accent:#66c6b2; --s-accent-soft:rgba(102,198,178,.12); --s-accent-line:rgba(102,198,178,.32); --s-on-accent:#0d1a17;
  --s-up:#5ec48c; --s-down:#e0818b; --s-down-soft:rgba(224,129,139,.1); --s-warn:#d5a75c;
  --s-btn-bg:#e7edf0; --s-btn-ink:#10171b; --s-focus:rgba(102,198,178,.25);
  --s-switch-off:#3b4750;
  --s-shadow:0 1px 2px rgba(0,0,0,.28),0 12px 30px -20px rgba(0,0,0,.7);
  }
}
```

要点：侧栏和主区域同一底色（`--s-page`），只有一条 `--s-border` 细线分隔。页面上不使用纯白或纯黑。强调色是深青绿，只用于选中态、链接、焦点环和计量条，不做大面积填充。

实现约定：

- 变量挂在 `.settings-root` 类上，这个类加在 `extension-pages/options.html` 的 `<body>` 上，不写到 `:root`。`src/react/globals.css` 是三个扩展页面共用的，写到 `:root` 会改到浮窗和侧边栏。
- 统一加 `--s-` 前缀。shadcn 已经占用了 `--border`、`--accent` 等同名变量，含义不同（shadcn 的 `--accent` 是悬停底色，不是强调色），不加前缀会互相覆盖。
- 深色模式跟随系统，和项目现有做法一致（`globals.css` 里的 `@custom-variant dark` 用的是 `prefers-color-scheme`）。不加 `data-theme` 属性，不新增主题设置项。
- 设置页里继续用到的 shadcn 组件（如 Select 的下拉层），在 `.settings-root` 内把 shadcn 变量映射到上面这组颜色。类加在 `<body>` 上，Radix 渲染到 `body` 下的弹出层也能拿到这些变量。

## 2. 排版与间距

字体：`-apple-system, BlinkMacSystemFont, "PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", sans-serif`，正文 14px / 行高 1.6。数字用 `font-variant-numeric: tabular-nums`。

| 用途 | 字号 / 行高 / 字重 |
|---|---|
| 页面标题 | 26px / 1.3 / 600，字距 -0.015em |
| 页面说明 | 13px / 1.65 / 400，`--s-ink-3` |
| 分组标题 | 15px / 1.45 / 600 |
| 分组说明 | 12.5px / 1.65 / 400，`--s-ink-3` |
| 字段标签 | 13px / 1.5 / 500，`--s-ink-2` |
| 输入文字 | 13.5px |
| 辅助说明 | 12px / 1.6，`--s-ink-3` |
| 行标题（列表项） | 13.5px / 1.5 / 500 |
| 行附加信息 | 12px，`--s-ink-3` |
| 侧栏卡片标题 | 12.5px / 600 |
| 侧栏分数 | 30px / 1 / 600，字距 -0.02em |

间距：页面内边距 `48px 48px 96px`，内容最大宽度 1140px。分组之间用 `28px 0 30px` 加一条顶部分隔线；第一个分组去掉上边距。分组标题下方 14px。字段之间上下 11px。标题上方的留白必须大于下方。

## 3. 外壳

- 网格：`248px minmax(0,1fr)`，最小高度 100vh。
- 侧栏：吸顶，高 100vh，内边距 `30px 18px 22px`，纵向排列：品牌 → 导航 → 底部版本号。品牌是 30px 方形图标（`--s-inset` 底、`--s-border` 边）加 13.5px 名称。导航项高约 34px（`9px 10px` 内边距）、圆角 8px、13.5px、`--s-ink-2`；悬停 `--s-surface-2`；选中 `--s-inset` 底 + `--s-ink-1` + 600 字重，**不加彩色竖条**。导航项前有一个 16px 线性图标（人像 / 接口 / 漏斗 / 齿轮）。
- 底部：版本号（12px `--s-ink-3`），下一行是弱链「检查更新」和更弱的「更新日志」，中间用「·」分开。上方仍是一条 `--s-border` 细线。不要画示意用的虚线框。「检查更新」留在当前通道，并触发本页「关于与更新」里的同一次检查与安装结果。「更新日志」把主区换成独立页（`#changelog`），设置壳保留左栏和版本行；顶栏「‹ 设置」回到进入前的设置页。停在日志页时「更新日志」用强调色加下划线，左侧四个导航项不显示选中态。时间线列出当前通道的 GitHub Release（稳定只保留正式版，预览保留预发布）：左竖线与节点、版本号、与已安装版本一致时的「当前」徽标、`YYYY-MM-DD HH:mm`，下面是条目。条目去掉「预览：」「稳定：」、issue 号和「方案 X」代号。右上角弱链可以去 GitHub Releases。窄屏（≤860px）仍隐藏版本行；直接打开 `#changelog` 仍显示这一页。
- 页头：标题 + 右侧保存状态，下方 `--s-border` 细线，与内容间距 32px。设置页如此。更新日志页的顶栏另计：内边距 `18px 28px 14px`，返回链在标题上 8px，标题 20px，说明在标题下 4px；时间线块间距 22px，版本行与条目间距 8px，条目间距 5px。
- 保存状态：6px 圆点（已保存用 `--s-up`）+ 12px 文字 `--s-ink-3`。三种：`保存中…`、`已自动保存 · 14:32`、`保存失败，重试`（失败时圆点用 `--s-down`，文字可点击或作为按钮重试）。
- 页面切换：`#profile` / `#ai` / `#filters` / `#general` 四个 hash，刷新后保持当前页。`#changelog` 只打开更新日志，不增加导航项，也不改这四个 hash 的含义。更新完成后打开设置页会带 `#updated`：此时显示更新完成提示，并落在「通用与隐私」页。进入日志页之前不要把 `#updated` 改写成 `#general`。
- 内容载体是「分组」，不是卡片：不加边框、圆角、阴影、嵌套。分组之间只靠留白和细线。

## 4. 组件

**字段**：两列网格 `132px minmax(0,1fr)`，标签在左、控件在右、间距 18px。窄屏（≤860px）改为上下排列、间距 7px，标签取消上内边距。

**输入框**：高 36px，圆角 8px，`--s-field` 底，`--s-border-strong` 边；聚焦时边框转 `--s-accent` 并带 3px `--s-focus` 光晕。数字输入的短版宽 88px、高 34px。文本域最小高 76px。

**标签输入（chips）**：容器 `--s-field` 底、圆角 8px、内边距 `6px 8px`；标签高 24px、圆角 6px、`--s-inset` 底，右侧一个 18px 的 × 按钮。空容器里显示提示文字（如「回车添加」）。交互不变：回车或逗号确认、输入为空时退格删除最后一个、去重不区分大小写、失焦时提交。风险词标签用 `--s-down-soft` 底、`--s-down` 字。

**按钮**：高 32px、圆角 8px、13px / 500，内边距 `0 12px`；小号 28px。主按钮 `--s-btn-bg` 底 + `--s-btn-ink` 字（深色模式下自动反转）；描边按钮 `--s-surface` 底 + `--s-border-strong` 边；幽灵按钮无底色；危险按钮只有 `--s-down` 字和 32% 透明度的 `--s-down` 边。禁用态 45% 不透明。

**开关**：36×21px 胶囊，关闭时 `--s-switch-off`，打开时 `--s-accent`，滑块 15px 白色圆点带阴影。可点区域整行。开关行左右分置，下方 `--s-border` 细线，最后一行去掉。

**分段控件**：`--s-inset` 底、圆角 9px、内边距 3px；选中项 `--s-surface` 底 + 细边 + 阴影，字重 500。

**单选卡片**：三列网格，`--s-field` 底、圆角 10px、内边距 `12px 13px`；选中时 `--s-accent-soft` 底、`--s-accent-line` 边、内部 14px 圆点填充。整张卡可点，键盘可达。

**拖放区**：虚线 `--s-border-strong` 边、圆角 10px、`--s-surface-2` 底、内边距 `26px 22px`、居中；悬停变 `--s-accent-line` 边和 `--s-accent-soft` 底。

**列表行**：左右分置，`14px 0` 内边距，行间 `--s-border` 细线。左侧标题行可带状态徽标，下方一行附加信息（协议 · 模型 · 地址，模型名用等宽字体加 `--s-inset` 底）；右侧是操作按钮组。

**折叠区**：`details/summary`，summary 12.5px `--s-ink-2`，前面一个 `›`，展开时旋转 90°。高级设置用虚线顶边，手动更新步骤用实线顶边。

**徽标**：高 20px、圆角 5px、11.5px；强调徽标用 `--s-accent-soft` 底 + `--s-accent` 字；「正在使用」带一个 5px 圆点。

**侧栏卡片**：296px 宽，`--s-surface` 底、圆角 14px、内边距 `20px`、`--s-shadow`，吸顶 38px。窄屏（≤1080px）移到表单前，待补充项按可用宽度排列。

**危险操作区**：一行，左侧标题 + 一句后果说明，右侧危险按钮；与普通分组用细线分隔。

**忙碌遮罩**：处理中给整页加 `inert`，并保留 `role="status" aria-live` 的提示；错误用 `role="alert"`。

## 5. 各页面结构与字段来源

### 个人画像（双栏，右侧 296px）

1. **导入材料**：分段控件（简历文件 / 粘贴文本 / 画像 JSON）+ 拖放区。说明只保留一句：「抽取时文本会发给当前启用的 AI，确认后才写入画像。」
   - 简历文件 → `parseResumeFile` → `AI_RESUME_EXTRACT`
   - 粘贴文本 → `AI_RESUME_EXTRACT`
   - 画像 JSON → 校验字段后单独导入
   - 多文件按 10000 字一段提取，再用 `mergeDraft` 合并
   - **新增规则**：单个文件超过 10 MB 拒绝导入并提示
   - 抽取结果在独立对话框中预览，长内容在对话框内滚动，操作保持可见；用户选择合并 / 替换 / 放弃。关闭对话框等同放弃草稿。
2. **求职目标**：目标岗位、目标城市、期望月薪（下限 / 上限 + k/月）、目标行业、公司规模、办公方式。来源 `profile.target.*`。「只用于匹配打分，不会写进招呼语」这句保留在期望月薪下。
3. **个人基础**：最高学历、当前或最近职位、姓名、工作年限。来源 `profile.basics.*`。姓名留空即不填。
4. **能力与经历**：专业技能、优势亮点、行业经验、工作经历概述、项目经历概述、核心成就。来源 `profile.capabilities.*`、`profile.workSummary`、`profile.projectSummary`、`profile.highlights`。「AI 撰写招呼语时只会引用这里写到的事实」保留在项目经历下。
5. **偏好与禁区**：雷点、给 AI 的说明。雷点只有一个标签输入入口，同时显示 `profile.preference.avoidKeywords` 和 `profile.preference.dealbreakers` 中已保存的内容；说明为「字面或 AI 语义命中都会降低匹配分，岗位仍会保留」。两个存储字段保持原名，不合并、不改名。
6. **清除画像**：危险操作区，二次确认；同时清掉匹配缓存。
7. **右侧栏**：画像完整度。分数、`N / 11 项`、计量条、待补充项列表。评分沿用 `scoreProfile` 的 11 项，**不改评分规则**。

### 模型接口（单栏，最大 760px）

1. **已添加的接口**：预设下拉 + 添加按钮；下方每个接口一行——名称、可选「正在使用」徽标、`协议 · 模型 · 主机`，右侧「测试连接 / 设为使用 / 编辑」。
2. **编辑区**：只编辑当前选中的接口。字段：名称、协议（四段分段控件）、接口地址（辅助说明：填到 `/v1` 为止）、模型（带已拉取模型的候选）、API Key（默认隐藏 + 显示按钮）。底部一行：测试连接结果徽标（`连接正常 · 0.8 秒`，耗时由界面计时）。**保留自动保存，不出现保存按钮**。
   - 高级设置折叠：temperature、maxTokens、请求地址、模型列表地址、额外请求头（JSON，格式错误要有提示）
   - 拉取模型：写入候选列表
3. **删除这个接口**：危险操作区，二次确认；删除正在使用的接口后要处理启用状态。

### 岗位筛选（单栏，最大 760px）

1. **启用本地筛选**：单行开关，说明「关闭时列表显示全部岗位，并标注命中的规则」。侧边栏列表顶部有同一字段的「开启过滤」开关，两处双向同步。
2. **关键词**：包含任一、排除、风险词（风险词标签用危险色，说明「只在岗位上标注提醒，筛选关闭时也生效」）。来源 `filters.keywordsInclude / keywordsExclude / riskKeywords`。
3. **公司与城市**：屏蔽公司、城市。来源 `filters.excludeCompanies / cities`。
4. **薪资与要求**：月薪下限（说明「岗位最高薪资低于这个数就不显示」）；折叠区里放经验偏好、学历偏好（说明「只记录为不符合的原因，不会隐藏岗位」）。
   - `salaryMaxK` 界面不显示，但必须原样保留，不能被清空。

### 通用与隐私（单栏，最大 760px）

1. **运行平台**：三张单选卡片——跟随当前网站 / 只用 BOSS 直聘 / 只用前程无忧。对应 `settings.mode` 的 `auto` / `boss` / `qcwy`。
2. **收录与分析**：自动收录岗位；自动 AI 分析（「每个新岗位消耗一次接口调用。」）；显示收录角标（「显示在招聘网站页面右下角。」）；合并重复岗位。对应 `autoCapture`、`autoScore`、`showBadge`、`dedupe`。岗位库上限对应 `maxJobs`，说明「超出后先淘汰最早收录的，收藏的岗位不会被淘汰」。
3. **隐私**：发送前脱敏（含「不能保证移除所有个人信息」）、发送岗位公司名、发送招呼语前确认。对应 `privacy.redactPII / sendCompanyName / confirmBeforeSend`。
4. **岗位数据**：说明行「已收录 N 个，其中收藏 M 个，上限 X 个」——用 `JOB_LIST_REQUEST` 的返回统计，不新增消息。两行：导出岗位（JSON / CSV，辅助说明「只有 JSON 可以用来恢复」）；清空岗位库（危险色，二次确认，提示「建议先导出 JSON」）。
5. **关于与更新**：见下。

### 关于与更新

1. 说明一行：「解压出来的文件夹就是扩展本身。请放在固定位置，不要删除或移动。」
2. 更新通道：两张单选「稳定 | 预览」，默认稳定，对应 `settings.updateChannel`（`'stable' | 'preview'`，缺省按稳定）。稳定只检查正式版；预览只检查 GitHub 预发布。辅助说明：「预览只检查 GitHub 预发布包。正式版更旧时不会自动降级。」
3. 版本行：当前版本号、可选「可更新到 x.y.z」徽标、扩展文件夹与授权状态；右侧「检查更新」和「更新到 x.y.z」。侧栏底部的「检查更新」不另做结果区，只调用这里的检查；有新版本时仍用本面板的「更新到 x.y.z」和安装过程。
4. 发布说明卡：版本号 + 日期、GitHub 链接、更新内容列表。
5. 一句「更新后扩展会自动重新加载，岗位、画像和配置都会保留。」
6. 折叠：自动更新失败时的手动更新步骤（下载 zip → 覆盖原文件夹 → 扩展管理页点「重新加载」）+「打开扩展管理页」按钮。
7. 扩展 ID，等宽字体。

状态必须覆盖：检查中、已是最新、有新版本、暂无预览版、当前版本高于正式版（提示手动下载正式 zip 覆盖，给出正式版发布页和「打开扩展管理页」，不自动降级）、下载进度、浏览器不支持、取消选择文件夹、下载失败后显示手动步骤。点击安装后必须立即弹出文件夹选择窗口，中间不能先等待其他异步操作。

## 6. 文案规则

遵循 `DESIGN.md` 的「设计原则」：分组、标题和控件形态已经表达清楚的，不再用描述重复。辅助说明只留给用户从界面上看不出来、又会影响决定的信息——费用、数据发往哪里、不可撤销的后果、不符合直觉的规则。上文中保留的说明句都是这一类，其余不要新增。

## 7. 响应式

- ≤1080px：完整度从右侧移到表单前，待补充项随宽度分列。
- ≤860px：侧栏变成顶部一行、可横向滚动；导航隐藏图标外的装饰，只保留文字；页面内边距 `24px 18px 80px`；字段改为上下排列；单选卡片与两列网格改单列；页头改为纵向。

## 8. 验收

- 深浅色两套截图，宽屏与 ≤860px 窄屏各一份。
- 对比度不低于 4.5:1；不使用纯白 / 纯黑；没有超过 1px 的彩色左右边框；不在标题上方放小字标签（kicker）。
- 键盘可完成导航切换与所有开关操作；焦点环可见。
- 原有数据（岗位、画像、AI 配置、设置）在新界面上完整可用。
