## 所有工单应引用的共同约束

- 依据本目录 README 中已确认的 A 交互约束，以及仓库 AGENTS.md、DESIGN.md、岗位列表与偏好规格、设置页规格和领域文档。专项确认的新文案覆盖旧规格中的旧称，不改两层筛选的业务含义。
- 从当时最新的 `feat/vite-ui-roadmap` 开始，按仓库协作约定核查依赖并领取独立任务分支。任务分支不是本次拆分创建的。
- 使用真实扩展存储和既有消息完成业务闭环，但验证使用虚构岗位、模拟服务和隔离数据；不以真实简历、Key、招聘方或账号为前置条件。
- 不改存储字段名称和结构、消息类型名、固定构建输出和现有保存节奏。不引入代码分割，不调整安装时文件夹选择的调用顺序。
- AI 匹配分、雷点和规避关键词不自动隐藏岗位；岗位筛选决定可见性；风险词只提醒。自动打分是否跳过岗位继续服从既有筛选规则。
- 全选、新批量操作和导出只覆盖当前可见范围；隐藏的选中项另计。进行中队列的范围由启动时的快照决定。
- 每项完成后运行 `npm test` 与 `npm run build`，并执行与该项有关的浏览器检查。逻辑通过不等于界面验收通过；未执行的真实扩展检查明确记录。
- 界面在 320/390/480px、浅深色下可用，无横向溢出；焦点可见，图标有可访问名称。按已确认的颜色、尺寸和状态验证实际渲染。
- 不把原型源码直接作为生产架构搬入；不引入真实投递、自动发送或反检测功能。

## 共享规格发布门槛

工单发布前，将已确认的视觉、尺寸、文案和状态决定写成可从 GitHub 读取的规格，并记录 #30 的用户确认。原型源码和截图仍只在本机时，应明确这一点，不给不存在的远端文件或分支内容提供链接。

`ready-for-agent` 表示材料完整。只有规格可共享且没有未关闭 blocker 的任务可以领取；有明确前置任务时同时用 `blocked` 并设置 GitHub 原生依赖。实际材料状态、标签、依赖和领取情况以 GitHub 为准。

正式开发应同步修订旧的设置规格和岗位列表规格中的开关名称，避免接手者同时读到“开启过滤”“启用本地筛选”和“应用筛选规则”三种现行称呼。稳定代码入口和消息清单可放在共享交接规格中，工单正文以行为和验收为主。

## S5 · #36：岗位流程以打招呼为第一步

### Parent

#29

### Type

AFK。

### What to build

将原招呼语详情改为“流程”。竖向步骤条的第一步为“打招呼”，用户依次准备招呼语、尝试打开沟通，再手动确认已经发送；列表流程入口和状态始终反映实际记录。

### Acceptance criteria

- [ ] 竖向流程以“打招呼”为第一步，小步骤为“准备招呼语 / 尝试打开沟通 / 手动确认发送”；区分当前、已完成和待进行，不能只靠颜色表达。
- [ ] 继续使用既有进度：无记录为“待打招呼”，`prepared` 为“招呼语已准备”，`opened` 为“待确认发送”，`sent` 为“已发送（手动确认）”。此映射来自已确认原型，不新增业务状态或存储结构。
- [ ] 每种状态只保留一个主要推进动作；行内入口分别为“打招呼 / 继续流程 / 确认发送 / 查看流程”。
- [ ] 支持既有招呼语版本、编辑、保存、字数、复制和明确的重新生成；复用原有保存语义，保存失败不提前记录准备完成，重新生成不悄悄覆盖未保存编辑。
- [ ] 尝试打开沟通沿用已有入口和必要的确认；打开失败说明原因，不记为成功。复制和尝试打开均不表示已发送；已确认发送的进度不得因重复打开而回退。
- [ ] 只有用户明确手动确认才写入 `sent`，确认失败保留原阶段；确认成功显示持续可见的发送记录。
- [ ] “后续流程 / 待扩展”只作视觉占位，不提供无法执行的动作，不虚构面试等后续业务状态。
- [ ] 以模拟导航/剪贴板/消息走通各阶段及失败路径，检查旧进度兼容、列表和详情一致；完成共同工程验证。不得用真实招聘方验证发送。

### Acceptance criteria

- [ ] “停止后续”只阻止下一项开始，当前请求仍可完成；停止后的成功、失败和未执行计数准确，不能声称已中断已发请求。
- [ ] 重试失败与继续未执行仅作用于对应集合，并创建一轮明确的新队列；找不到或已删除的岗位给出可理解的跳过记录，不意外处理其他岗位。
- [ ] “准备未处理岗位”复用现有分析及招呼语能力，仅在准备成功后记录 `prepared`，不覆盖已推进的状态；“处理下一个”只进入对应流程并沿用手动沟通语义，不自动发送。
- [ ] 结果在当前侧栏会话内可回看；本切片不新增存储键或后台队列协议。侧栏重开不自动重放请求，不承诺跨刷新恢复队列。
- [ ] 模拟串行任务验证首项失败继续、执行中停止、范围快照、仅重试失败、仅继续未执行、岗位删除及准备状态；完成共同工程验证与窄屏、深浅色、键盘检查。

用户可以导出当前可见岗位，或仅导出当前可见且选中的岗位，提前看清数量。保持现有详细 CSV 字段、转义和下载行为兼容。

### Acceptance criteria

- [ ] 未选择时导出当前可见列表；有选择时仅导出可见且选中项。按钮明确表示范围和数量，隐藏选中不进入文件。
- [ ] 所选岗位均被隐藏时不悄悄改为导出全部可见项；明确提示当前没有可导出的可见选中岗位，并允许清空选择。
- [ ] 导出使用触发时确定的范围；触发后改变筛选不暗改这次导出，空范围禁止导出。
- [ ] 保留现有详细 CSV 字段和岗位数据含义，正确处理中文、引号、逗号、换行及缺失值，不重做导出协议。
- [ ] 下载或导出失败有可见错误和重试路径，不清空用户选择或伪报成功。
- [ ] 用虚构数据核对实际 CSV 的行数、标识和字段，覆盖规则开关、平台筛选、隐藏选择与空范围；完成共同工程验证。
