## 运行原型

在本工作区执行：

```sh
npm run prototype:list
```

首次检出需先 `npm ci`。发布内容不包含 `node_modules` 或依赖锁文件修改。

[打开 A · 紧凑清单](http://127.0.0.1:5291/sidepanel-prototype.html?variant=A&width=390&theme=light)。页面顶部可切换 320 / 390 / 480px、深浅色、空库 / 加载 / 失败场景。评审导航只保留 A，已移除浮动结构切换器及其全局左右键监听。B/C 源码仅保留为前轮探索记录，不再参与本轮比较。

原型入口：`extension-pages/sidepanel-prototype.html`，交互与样式在相邻 `src/react/sidepanel-prototype.{jsx,css}`。使用独立相邻入口隔离真实数据及扩展副作用；现有生产构建 input 不含该入口。

## A 交互约束（用户已确认）

- 结构延续设置页的中性色、深青强调色、系统字体和细分隔线；不用大卡片堆叠。
- 进入详情后隐藏列表搜索、筛选和批量栏；返回时恢复原滚动位置与标题焦点，以轻微底色及“刚看过”提示定位原岗位。
- 行内按岗位信息 → 匹配与流程入口 → 单行分析摘要 → 规则与风险提醒排列。匹配分、结论位于左侧，右侧提供“打招呼 / 继续流程 / 确认发送 / 查看流程”；不再额外增加底部动作行。摘要截断后可点击匹配结果查看全文。
- 筛选开关统一为“应用筛选规则”，说明统一为“隐藏不符合规则的岗位；关闭后仍标注原因。”列表、筛选弹窗、规则设置预览及状态栏使用同一文案。重置视图不改变开关。
- 筛选弹窗保留“调整规则”入口。本原型打开内存模拟的岗位筛选设置，编辑后立即更新命中原因；“返回筛选岗位”回到弹窗。正式开发时接入设置页“岗位筛选”，复用同一个存储字段。
- 风险直接说明需要确认的事情；排除条件使用提示区域、筛选图标、“应用筛选规则后将隐藏”和具体命中原因，不只依赖颜色。风险词只提醒，AI 评分不参与规则隐藏。
- 收藏入口用于集中回看；收藏岗位不参与岗位库超额自动清理。原型只演示收藏筛选，不模拟淘汰。
- 已分析分数打开已有结果，重新分析在结果内部单独触发。
- 原“招呼语”详情标签改为“流程”。竖向步骤条以“打招呼”为第一步，包含准备招呼语 → 尝试打开沟通 → 手动确认发送；分别表现当前、已完成与待进行的小步骤，每种状态只保留一个主要推进动作。
- 进度使用“待打招呼 / 招呼语已准备 / 待确认发送 / 已发送（手动确认）”。打开沟通不能证明已发送，只有明确手动确认才记为发送。“后续流程 / 待扩展”仅为占位，不定义后续业务状态，不新增存储字段。
- 主按钮悬停时同步指定背景、文字与边框颜色，深浅色均保持对比；成功提示在弹窗打开期间隐藏，避免遮挡弹窗内容与按钮。
- 全选、导出、批量分析以当前可见项为范围；被筛选隐藏的选中项单独计数，不参加新操作。
- 队列开始时快照所选项；之后改变筛选不暗改进行中的队列。第一项失败继续后续；停止只阻止下一项开始，当前请求仍可能完成。失败原因持续留在队列，支持重试失败与继续未执行项。
- 不喜欢、复制、导出、打开原岗位、打开沟通均为本地演示，不操作真实数据或招聘网站。画像保存节奏、存储字段、进度 key、消息名与构建文件名沿用现有契约。

## 评审方式

用同一组 8 条虚构岗位评审 A。先看 390×820 默认首屏，检查标题、公司、薪资、匹配摘要和流程入口能否连续扫读；再用第二条的风险、第四条的长标题、第五和第七条的排除原因判断层级。普通第一行约 174.7px，三个宽度均能完整显示三条；风险、排除和长标题按内容增高。

点击“筛选 → 调整规则 → 返回筛选岗位”检查说明、设置入口与开关一致性。点击第一条的“打招呼”，观察竖向流程中的当前步骤变化及发送确认。可点击“全选 → 分析”观察模拟队列；场景切换和重置模拟数据只用于原型评审。

原型截图与走查结果见 [verification.md](verification.md)。A 的结构、密度、用语与流程细节均已获用户确认，正式实现以本节交互和视觉约束为依据。八个实现切片对应 #31、#34、#35、#32、#36、#37、#33、#38。原型分支作为设计依据保留，不应整体合入生产；规格读取与正式开发基线见 [handoff.md](handoff.md)。实时标签、占用、原生依赖和开发进度以 GitHub 为准。
